# HeroUI-first RTL Design System Specification

## IT Ticketing Platform — User App + Dashboard App

Version: 1.0
Theme: Light Mode Only
Direction: RTL First
UI Language: Persian
Technical Specification Language: English

---

# Board 01 — Design Principles & System Scope

## 1. Product Scope

### User App

* Purpose: End-user ticket submission and tracking.
* Primary platform: Mobile responsive.
* Main flows:

  * Login
  * Register
  * Create Ticket
  * My Tickets
  * Ticket Details / Conversation
  * Notifications
  * Profile / Account Settings

### Dashboard App

* Purpose: Management panel for Admin and Support.
* Primary platform: Desktop-first.
* Main flows:

  * Dashboard Overview
  * Tickets Management
  * Ticket Details
  * Users Management
  * Support Management
  * Departments Management
  * Reports
  * Notifications
  * Profile

### Admin View

* Admin count: Only one Admin exists in the system.
* Admin has full visibility and full management permissions.
* Admin can manage:

  * Users
  * Supports
  * Departments
  * Tickets
  * Reports
  * Manual Assignment
  * System-level configurations

### Support View

* Support has role-aware and permission-aware access.
* Support can see:

  * Assigned tickets
  * Department tickets
  * Notifications
  * Profile
* Support profile permissions and departments are read-only.
* Support cannot edit their own permissions/departments.

---

## 2. Core Flows

### Authentication

* Users, Supports, and Admin enter through login.
* After login, the system redirects based on role:

  * User → User App
  * Admin → Dashboard App / Admin View
  * Support → Dashboard App / Support View

### Ticket Creation

* User creates a ticket with:

  * Title
  * Department
  * Description
  * Attachments
* System creates:

  * Ticket
  * Initial message
  * Assignment
  * Notification

### Ticket Conversation

* Ticket conversation is not real-time chat.
* Use a threaded support conversation layout.
* Message types:

  * User Message
  * Support Message
  * System Message

### Notifications

* Notification delivery pattern:

  * In-app notification list
  * Browser push support later
* Notification states:

  * Read
  * Unread
  * Highlighted

### Reports

* Reports section must include:

  * KPI cards
  * Ticket trends
  * Department statistics
  * Support performance
  * Export report modal

### User / Support / Department Management

* Admin manages users, supports, and departments.
* Support edit flow must allow Admin to update:

  * Name
  * Username
  * Password
  * Departments
  * Permissions
  * Availability status

---

## 3. UX Goals

### Clarity

* UI must clearly show:

  * Ticket status
  * Assigned support
  * Department
  * Last update
  * Available actions

### Fast Task Completion

* Primary actions must be visible near the page title or main content.
* Avoid hiding important actions behind too many menus.

### Low Cognitive Load

* Use consistent layout patterns.
* Use semantic colors only for status and feedback.
* Keep forms grouped into logical sections.

### Scannable Ticket Workflows

* Ticket list rows/cards must show:

  * Ticket ID
  * Title
  * Status
  * Department
  * User
  * Assignee
  * Last update
  * Actions

### Permission-aware UI

* Only show actions that the current role/permission can perform.
* Disabled actions should include tooltip or helper reason where needed.

### Responsive User App

* User App must work properly on mobile.
* Dashboard is desktop-first, but table pages should degrade gracefully.

---

## 4. Visual Direction

### Style Keywords

* Modern
* Clean
* Professional
* Trustworthy
* Calm
* Support-centric

### Visual Personality

* Enterprise SaaS
* Friendly but not playful
* Low-noise interface
* Strong hierarchy
* Soft surfaces
* Clear actions

### General Surface Style

* Background: very light neutral
* Cards: white/elevated
* Borders: subtle neutral
* Shadows: soft
* Radius: medium-to-large
* Accent: blue/indigo system

---

## 5. Role-Based Strategy

### Admin

* Full navigation.
* Full table visibility.
* Full report access.
* Manual assignment access.
* Support edit access.
* Department management access.

### Support

* Reduced navigation.
* Focus on:

  * Dashboard
  * My Tickets
  * All Department Tickets
  * Notifications
  * Profile
* Permissions and departments shown as read-only in profile.

### User

* Simple navigation.
* Focus on:

  * Create Ticket
  * My Tickets
  * Ticket Conversation
  * Notifications
  * Profile

---

## 6. HeroUI Strategy

### HeroUI Primitives

Use HeroUI components as the base for:

* Button
* Input
* Textarea
* Select
* Autocomplete
* Card
* Table
* Modal
* Chip
* Avatar
* Badge
* Pagination
* Tabs
* Dropdown

* Radio
* Switch
* Tooltip

### Custom Domain Components

Build custom wrappers on top of HeroUI for:

* Ticket Status Chip
* Availability Chip
* Ticket Info Panel
* Ticket Action Toolbar
* Message Bubble
* Message Composer
* Assignment History
* Status History
* Report Export Modal
* Manual Assignment Drawer
* Filter Bar
* Dashboard Metric Card

---

## 7. Responsive Strategy

### User App

* Mobile-first.
* Main mobile width target: 360px.
* Page horizontal padding: 16px.
* Bottom navigation height: 64px.
* Primary CTA should be reachable with one hand.

### Dashboard App

* Desktop-first.
* Minimum recommended dashboard width: 1024px.
* Main layout:

  * Right sidebar
  * Top header
  * Content area
* Tables remain primary layout on desktop.
* On smaller screens, tables transform into stacked cards.

---

## 8. Implementation Context

### Frontend

* React
* Next.js App Router
* React Query
* Tailwind CSS
* HeroUI

### Backend

* NestJS API

### Direction

* `dir="rtl"` at document/app shell level.
* Use RTL-aware spacing and alignment.
* Icons should appear on the correct side for RTL layout.

# Board 03 — Typography, Iconography & Content Rules

## 1. Font System

### Persian Primary Font

* Preferred: `IRANSansX`
* Fallback: `Vazirmatn`, `Tahoma`, `sans-serif`
* Usage: All Persian UI content.

### Latin / Technical Font

* Preferred: `Inter`
* Fallback: `Roboto`, `Arial`, `sans-serif`
* Usage:

  * English technical annotations
  * IDs
  * Numbers when needed
  * Developer-facing labels

### Monospace Font

* Preferred: `JetBrains Mono`
* Fallback: `ui-monospace`, `SFMono-Regular`, `Consolas`
* Usage:

  * Ticket IDs
  * API-like keys

## 3. RTL Text Rules

### Alignment

* Persian text: right aligned.
* Form labels: right aligned.
* Table headers: right aligned unless numeric.
* Numeric columns: use consistent alignment; preferably center or left only for IDs when visually needed.
* Actions in RTL: usually placed on the left side of rows/cards.

### Mixed Persian / English

* Add spacing around Latin IDs:

  * Correct: `تیکت #TK-1024 ایجاد شد`
  * Avoid: `تیکت#TK-1024ایجاد شد`
* Ticket IDs should use LTR isolation:

  * CSS: `unicode-bidi: isolate; direction: ltr;`

### Text Truncation

* Single-line overflow:

  * `white-space: nowrap`
  * `overflow: hidden`
  * `text-overflow: ellipsis`
* Multi-line body:

  * Use max 2–3 lines in cards.
  * Full text visible in detail pages.

### Page Titles

* Short and direct.
* Examples:

  * `داشبورد`
  * `تیکت‌های من`
  * `همه تیکت‌ها`
  * `ایجاد درخواست`
  * `گزارش‌ها`

### Card Headings

* Use noun phrases.
* Examples:

  * `تیکت‌های باز`
  * `میانگین زمان پاسخ`
  * `عملکرد پشتیبان‌ها`

### Action Labels

* Use clear verbs.
* Examples:

  * `ایجاد تیکت`
  * `ارسال پیام`
  * `ذخیره تغییرات`
  * `دریافت گزارش`
  * `تخصیص پشتیبان`

### Empty States

* Explain state + give next action.
* Example:

  * `هنوز تیکتی ثبت نشده است.`
  * CTA: `ایجاد تیکت جدید`

### Error Messages

* Clear, specific, recoverable.
* Example:

  * `نام کاربری الزامی است.`
  * `فرمت فایل پشتیبانی نمی‌شود.`

* background → #FAFAFA
* content1 → #FFFFFF

* content3 → #F1F5F9
* focus → #2563EB

## Global CSS Direction

At root:

* `dir="rtl"`
* `lang="fa"`

Recommended CSS:

* `html { direction: rtl; }`
* Use logical properties:

  * `padding-inline`
  * `margin-inline`
  * `border-inline`
  * `inset-inline-start`
  * `inset-inline-end`

Avoid hard-coded:

* `left`
* `right`
* `margin-left`
* `margin-right`

Use logical alternatives where possible.

## Accessibility Rules

* Minimum contrast ratio for normal text: 4.5:1.
* Minimum touch target on mobile: 44px.
* Focus ring must be visible.
* Use icon + text for important states.
* Do not rely on color alone.
* Keyboard navigation must be supported in:

  * Modals
  * Drawers
  * Dropdowns
  * Tables
  * Forms

## Role-aware UI Rules

### Admin

* Full access.
* Can manage all data.
* Can manually assign tickets.
* Can export reports.

### Support

* Limited access.
* Can act based on permissions.
* Profile departments and permissions are read-only.

### User

* Can only access own tickets.
* Can send messages before ticket is closed.
* Can edit own profile and password.
